# CodeQL

CodeQL scans this repo's Python (`security-extended` + `code-quality`).
There is no hand-maintained findings catalog here — **the live status is
the scan output**, in two places:

- **CI:** the repo's **Security → Code scanning** tab (CodeQL runs
  automatically on push / PR).
- **Local:** [`.codeql-results/results.sarif`](../.codeql-results/results.sarif),
  regenerated by the run script below.

## Run it locally

After installing the CodeQL bundle once (see the header of
[`scripts/run-codeql.sh`](../scripts/run-codeql.sh)):

```bash
./scripts/run-codeql.sh
```

This rebuilds the database, runs both suites, applies the path filter from
[`.github/codeql/codeql-config.yml`](../.github/codeql/codeql-config.yml),
writes the SARIF, and prints a per-rule summary.

## Handling findings

**The goal is zero open alerts** — fix every actionable finding.

A few findings are by-design or CodeQL false positives and cannot be
code-fixed; **triage those by dismissing the alert in the Security tab**
with a reason (the rationale then lives on the alert itself). Known
recurring ones:

- `py/request-without-cert-validation` in `collector/src/redfish/*` —
  by design. BMCs ship with self-signed TLS certs by
  default; every call site threads the per-target `verify_ssl` flag, which
  is the real control point. Dismiss as *won't fix (by design)*. The rule
  stays enabled so any new site that hard-disables validation still
  surfaces.
- `py/unused-global-variable` on `amd_cper_sections._ACA_IDX_*` — false
  positive; used by the test suite. Dismiss as *used in tests*.

> CI note: CI scans via
> [`.github/workflows/codeql.yml`](../.github/workflows/codeql.yml)
> (advanced setup), which uses this `codeql-config.yml` so CI matches the
> local scan. GitHub's **default setup** must stay **off** for the repo, or
> the two conflict — disable it under Settings → Code security → Code
> scanning.

## Out of scope for CodeQL

Chase these with the right tool: dependency CVEs (`pip-audit`,
Dependabot), container CVEs (`trivy`), secrets in history (`gitleaks`),
and shell scripts (`shellcheck`, already in `setup-linters.sh`).
